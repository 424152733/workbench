# 保单合同整理（MVP）

## 入口与流程

在客户详情页上传单份 PDF 合同。服务端本地逐页解析，按保险责任、保额、保费、期间、免责、现金价值等关键词筛选短摘录；整理结果先供人工核对，用户确认后才可写入客户的保单档案，且新记录默认“待核实”。

扫描件当前只保存并提示无法识别，不调用 OCR。合同原件与客户保单档案使用独立表和独立文件目录，不进入面向公开产品资料的产品中心。

## Token 与截断控制

- 最多解析 300 页、25 MB 的 PDF；本地摘录最多 30,000 字，最多 10 个基础分块，每块不超过 3,000 字。
- 默认取合同前 3 页及包含保障、保费、责任免除等关键词的页面；每页只保留关键词附近的短窗口。超出筛选范围的页数、字符数、分块数会告知用户。
- AI 按分块顺序整理。合同字段抽取关闭思考模式，避免简单结构化输出把输出额度消耗在推理文本上；每次最多 2,000 个输出 tokens，每段最多提取 3 项重点保障。返回 `finish_reason=length`、JSON 不完整或空内容时，把该段再拆小，最多递归两层，且单次整理请求最多发起 16 次模型请求。
- 分块成功结果立即持久化。失败会留下失败状态并停止继续发送；“继续整理”会跳过已完成分块，重试未完成部分。未全部成功的结果标记为“部分完成”，不会显示为完整。
- 整理结果新增合同级保险金计算与给付方式概览，以及单项保障的给付方式；界面不展示逐字原文摘录。旧版已完成合同在用户重新确认授权并点击“更新整理结果”后，会从本地原 PDF 重新筛页再整理。
- 分块整理生成的“本段未提到”不能直接当成整份合同缺失。返回结果会按合同级保费、缴费期间、保障期间、基本保额和责任金额做本地交叉核对，过滤已被其他合同片段证实的信息；病种范围等细节仍保留一条简明核对提示。未核实合同不会被表述成客户没有对应保障。
- 当前整理版本会额外提取合同明确写出的生效日、固定到期日和下一次缴费日，并将可识别日期预填到保存表单。仅整理完整年月日，不从缴费年限、保单周年日或当前日期推算；“终身”不填固定到期日，下一次缴费日需以合同明确内容或实际缴费记录为准。旧版合同可在用户重新确认授权并主动更新后补充日期字段；已有 `coveragePeriod` 中明确的起始日期会本地预填，不额外调用模型。
- 合同明确标注的“基本保险金额”在本地按字段和数字规则提取，单独保存金额、页码，不占 AI 输入输出 tokens；归档保单时一并写入结构化字段。已归档的旧合同可在保障检视中手动点击“从原合同补提基本保额”，只读取本地 PDF，不覆盖已有且不一致的金额。
- 保存估算输入 token，并在服务返回后记录实际 prompt/completion/total tokens。估算按字符数粗略计算，不能代替服务端用量。
- 每段失败原因会在结果区展示，便于区分模型输出上限、无效 JSON、网络或服务错误；继续整理会跳过已成功片段。
- 原始 PDF 持续保存在本机工作台目录，直到用户删除。解析得到的全文不入库；仅暂存经过常见证件号、电话、保单号和姓名字段遮盖的筛选摘录，完整整理后自动清除这些摘录。部分整理时为支持续跑而暂存，用户删除合同可一并清除。

## 隐私与业务边界

- AI 请求只在用户勾选已取得客户授权并主动点击“开始 AI 整理”后发送；请求不包含原始 PDF 文件、客户档案名称或未筛选页面。
- 当前配置的 DeepSeek 服务会收到筛选摘录。正则遮盖只能处理常见格式，不能保证识别所有个人信息，因此仍要求取得授权并检查内容。
- 配置提示只比较系统中已经人工核实的保单险种，并提示先确认系统外的保障；不会给出产品购买、退保、理赔或适配结论。
- 输出保留合同页码和短证据摘录，但 AI 抽取不等于合同确认。保存后的保单仍为“待核实”，需对照正式合同复核；结论以合同及保险公司确认为准。

## 数据与文件

- `backend/migrations/015_customer_policy_contracts.sql` 创建客户合同整理记录，客户删除时数据库记录级联删除，保单删除时合同关联置空；`018_policy_contract_coverage_link.sql` 标记已删除保单对应的合同，不再纳入保障检视。
- 从客户保单列表删除保单时，关联的保障检视记录同步移除。合同 PDF 和整理结果保留在“保单合同整理”中，原“已归档”整理记录恢复为“已整理”；再次归档时会重新纳入保障检视。
- 原件存于 `backend/uploads/customer-policy-contracts/`，用户可在客户页删除合同及其分析记录。
- `policies.basic_sum_insured` 保存明确的基本保额；`customer_policy_contracts.local_facts` 保存本地确定性提取结果。
- API 按客户 ID 校验合同归属；上传限制为单个 PDF、25 MB。

## Excel 整理表导出

- “保单合同整理”提供 Excel 导出，按家庭保单模板的字段生成“家庭保单整理”和“保障责任明细”两个工作表，可容纳多份保单。
- 导出范围是当前客户保单档案，以及本机可读取的原合同保单页。合同即使尚未做 AI 整理，只要保单页能明确识别产品、日期和金额，也会列出；用产品名和生效日与已登记保单匹配，避免重复列出。险种名称只显示合同产品名称，不拼接核对状态；原合同无法读取时仍保留已保存的档案信息。
- 投保人、被保险人和受益人优先使用原合同保单页明确载明的角色；保险受益人不从投保人或被保险人猜测。性别、保障期间、交费期间、明确保额、保费和公司优先从保单页与档案取值。出生日期仅在原合同载明的身份证号通过本地校验时推得，并标记需人工核对；原身份证号不写入 Excel。职业仍无可靠来源，留空。
- “计划余交期数”按导出日之后的合同约定年交日期计算；有明确交费期满日的以该日期为界，否则按交费年限推算。一次交清显示该合同没有后续约定期数。此列不代表实际已缴、欠费、续保成功或保单仍有效。
- 概览按被保险人汇总各分类可识别的合同金额，使用数值单元格；缺少可核实金额时留空并在单元格备注中说明。重疾和身故分别按每份保单的基本保额或明确给付金额计一次，附加给付不与基本保额重复相加；实际身故给付仍受年龄、缴费和既往理赔等条款约束。住院报销优先采用年度共用上限，不把一般医疗与特定疾病医疗分项限额相加。意外门急诊仅计明确的意外门急诊责任，因意外导致的一般医疗费用不算独立意外保障。住院津贴按日额和一次性金额区分，不混加。“理财”仅计增额终身寿或年金产品的明确基本保额，不计现金价值、演示分红或未来领取额；不同分类之间不能合成一个总保额。保险责任仍优先根据原合同条款与保障计划生成短句和分行摘要，页码及给付条件在“保障责任明细”列出。
- 金额概览列按实际数值显示元；整数不显示无意义的小数，金额列保留足够宽度，避免 Excel 将金额显示为 `####`。
- 分类金额只计入截至整理日已生效且未明确到期的合同；原保期已过的合同仍保留在明细，但在金额单元格备注提示核对续保，未取得续保凭据前不计入当前保障。
- “意外身价”按意外身故可触发的合同基本保额统计：如重疾险的普通身故责任明确覆盖意外身故，也计入这一列。它可能与“寿险身价”指向同一份身故责任，两列不能相加；附加关爱金等有条件的额外给付暂不混入基本保额，仍按合同条款单独核对。
- 已删除保单关联的原合同虽保留在合同整理区，但不参与家庭保单导出及分类金额汇总；重新归档后恢复纳入。
- 年交保费小计只累计保费字段中明确标注年交频率的金额；频率不明的保费不计入小计并在表中说明。不同险种的保额、医疗限额和年金现金流不合并为一个总保额。
- 本地补提不调用 AI，不上传原合同。导出工作簿按模板字段重建，不带入原模板中的示例客户资料、账号或联系方式。

## 验证

实现后运行前端生产构建，并以当前客户的三份已上传合同做本地只读核对与导出检查；不调用付费模型。API 集成测试仅可对一次性测试数据库运行。
