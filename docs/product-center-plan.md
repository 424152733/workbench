# 产品中心模块规划

**版本：** 0.1（评审稿）
**日期：** 2026-10-17
**状态：** 已按评审意见完成首期 MVP 实施；具体实现和验证范围见 [产品中心实施记录](./product-center-implementation-report.md)

## 1. 模块定位

新增独立一级菜单「产品中心」，用于维护保险产品资料，并基于产品资料生成面向客户沟通和公开内容平台的产品解读。该模块与「大话保险」分开管理：

- 「大话保险」聚焦保险知识科普、常见误区和通用话题。
- 「产品中心」聚焦新华保险、人保财险等具体公司的具体产品、产品资料和产品解读内容。
- 产品中心生成的内容不进入大话保险的选题池，保留产品、资料版本和文案之间的关联。
- 可以复用现有的文章预览、草稿编辑、审核状态、复制等通用能力，但产品资料、产品提示词、内容来源和业务数据独立维护。

## 2. 用户与主要目标

当前用户是同时代理新华保险和人保财险的保险代理人。产品中心首期只启用新华保险产品档案；公司和险种字段采用可扩展字典，为后续启用人保财险等公司预留能力。主要目标是：

1. 把分散的产品说明书和产品资料整理为可检索、可复用的产品档案。
2. 借助 GPT 将产品条款和说明资料转成准确、易懂、简短的产品特点与价值介绍。
3. 基于同一产品资料，生成适合知乎、小红书和微信公众号的不同表达形式。
4. 在发布前人工核对和编辑，能够回到原始资料检查每一项产品事实。
5. 为后续智能保单说明书等功能准备结构清晰的产品资料基础。

## 3. 首期建议范围（MVP）

### 3.1 产品档案

产品档案建议包含：

- 保险公司：首期只允许创建新华保险产品；保险公司选项使用可扩展字典，后续可启用人保财险及其他公司。
- 险种分类：首期按新华保险实际产品维护可用险种；险种选项使用可扩展字典，后续可增加财险等分类。
- 产品名称、产品简称、产品状态、产品版本或适用日期。
- 简短备注、标签、创建时间和最近更新时间。
- 关联的官方资料及其文档类型、版本、上传时间。

产品状态可先使用「整理中」「可用」「已停用」。停用产品不再作为默认生成对象，但历史档案、草稿和来源资料继续可查看。

### 3.2 产品资料导入

首期支持上传可解析的 PDF、DOCX 和 TXT 资料。支持的具体格式应由文件解析能力和测试确定。扫描版 PDF、图片 OCR、表格复杂的费率材料可作为后续能力；无法可靠提取的内容应明确提示用户检查，不能静默地按完整资料处理。

每份资料记录：

- 文件名、资料类型（条款、产品说明、宣传材料、补充文件等）。
- 产品和版本关联、上传时间、资料日期（如能识别）。
- 解析状态及失败原因。
- 原始文件和解析文本之间的关联。

同一产品可关联多份资料。资料更新时创建新版本或新资料记录，避免覆盖后无法解释旧文案的依据；已经生成的文案保留其所依据的资料版本引用。删除和更新要区分处理：更新时保留旧版本；用户确认删除某份资料时，该资料版本关联的抽取结果、确认要点和文案草稿按级联规则一并删除。删除前展示将受影响的数据数量。

### 3.3 AI 产品要点整理

导入资料后，用户可以发起「提取产品要点」。结果先作为待核对的内部产品摘要，不自动视为已确认事实。建议字段：

- 产品定位：一句话说明产品类型和主要保障方向。
- 主要特点：每条包含「资料事实」「通俗解释」「可能对应的需求」「适用边界」「资料出处」。
- 责任与范围：资料能够明确支持的保障责任、给付或服务范围。
- 重要限制：等待期、免赔、除外责任、适用条件等仅在资料明确提及时列出。
- 待确认问题：资料缺失、表述冲突、识别不确定或需要人工判断的内容。

每一条可对外使用的事实都应尽可能关联到文件名、页码或章节。不能确认出处的内容应标为「待核对」，不能补猜。多份资料冲突时，展示冲突和两侧出处，让用户选择依据或修正产品档案。

### 3.4 生成平台文案

用户从已核对的产品要点中选择产品、资料版本和目标平台后生成文案。首期支持知乎、小红书和微信公众号，三种平台格式独立配置。允许先选择一个平台生成；多平台批量生成可在单平台流程稳定后加入。

小红书文案建议包含：

- 标题候选。
- 易读、精炼的分段正文，突出 3–5 个有资料依据的特点及其对应需求。
- 适合公开发布的话题标签建议。
- 可选的封面文案或图卡文字规划；是否在首期生成图片另行确认。

微信公众号文案建议包含：

- 标题和开篇引入。
- 产品类型、核心责任和特点的分段解释。
- 适用需求、容易误解的边界、需要读者留意的内容。
- 结尾总结和可选的常见问题。

知乎文案建议包含：

- 清晰回答一个具体问题，标题和开篇直接说明讨论的保障需求或产品问题。
- 解释相关保障责任、产品特点和关键概念，提供比小红书更充分的背景。
- 说明适用场景、重要限制和容易误解的地方；假设示例应明确标注为解释概念，不伪装成真实投保或理赔案例。
- 结尾归纳判断产品时应核对的事项，避免没有资料依据的排名或绝对推荐。

篇幅、标题风格和结构通过平台配置维护，不把字数、段数和表达风格写死在组件或提示词代码中。文案使用自然、易懂的中文，分组可使用「1、2、3」或合适的符号标题；不使用生硬的“第几步”叙述，也不输出 Markdown 加粗符号 `**`。

### 3.5 草稿审核与复制

生成内容进入产品中心自己的草稿列表，建议状态：

`生成中 → 待审核 → 已修改/已确认 → 已复制`。

- 用户可编辑、重新生成、保存版本、预览和复制。
- 重新生成不能覆盖已确认版本；旧版本保留以便比较和恢复。
- 预览复用现有知乎、公众号和小红书平台预览能力，并按所选平台展示。
- 发布维持人工操作：系统提供复制内容，不自动登录或发布到社交平台。
- 草稿显示产品、资料版本、平台、生成时间、审核状态和来源要点。

## 4. 核心使用流程

1. 进入「产品中心」，创建或选择产品档案。
2. 上传说明书、条款或其他产品资料，并为资料标注类型和版本。
3. 系统解析资料，展示解析状态；用户查看识别内容并确认或补充元数据。
4. 用户生成产品要点摘要，逐条核对事实、价值解释、边界和出处。
5. 用户选择知乎、小红书或微信公众号，基于已确认的产品要点生成对应文案。
6. 用户在平台预览中编辑、审核和保存版本，确认后复制到平台自行发布。

## 5. 内容质量与风险控制

- 仅根据已导入并关联的产品资料总结产品责任和特点，不虚构保费、收益、理赔结果、排名或承诺。
- 「产品特点」描述资料中的事实；「产品价值」解释事实可能对应的客户需求，两者分开呈现。
- 价值表达不能推导成对客户的个性化适配结论；首期不自动判断客户是否适合买某个产品。
- 不确定、缺失或互相矛盾的资料必须显式标记，并要求人工核对。
- 对公开内容保留人工审核和手动发布环节；AI 生成结果不被视为公司审批或合规结论。
- 生成结果提供资料出处供代理人核实；可配置为预览区显示，不默认混入最终公开文案。
- 生成接口应显式接收产品 ID、资料版本 ID、已确认要点、目标平台和平台配置，避免只传平台字段而丢失生成上下文。

## 6. 页面与导航建议

新增一级菜单「产品中心」，首期页面可分为：

1. 「产品库」：产品搜索、公司/险种筛选、状态、资料版本和最近更新时间。
2. 「产品档案」：产品基本信息、关联资料、AI 提取要点及待确认问题。
3. 「文案工作区」：选择平台、编辑文案、查看出处、预览、保存版本和复制。
4. 「产品草稿」：按产品、平台和审核状态筛选已生成的文案。

若首期页面数量需要控制，可把产品档案和文案工作区做成产品详情中的 Tab；导航仍保持产品中心独立，不在大话保险页面中混入产品列表。

## 7. 与现有模块的边界和复用

产品中心与「大话保险」的内容和业务状态独立，但实施时优先盘点并复用大话保险已经落地的通用组件和服务。不要为了增加菜单就复制一套编辑器、预览器、草稿操作或图片流程。

### 产品中心拥有

- 产品档案、产品资料和资料版本。
- 产品摘要、来源引用和人工确认状态。
- 产品专属提示词、平台文案配置和草稿关联关系。
- 产品资料更新后的影响追踪。

### 可复用现有通用能力

- 平台定义和频道顺序：`src/platforms.js` 中的 `channelNames`、`platformsForTopic`。产品中心使用相同的平台标识；若平台配置需要扩展，应增强共用配置，而非维护第二份平台名映射。
- 知乎与公众号富文本阅读预览：`src/article-preview.jsx`、`src/richText.js` 和 `src/features/content/article-preview.css`。预览可增加领域/署名/资料来源等显式配置，避免复制整套阅读器。
- 小红书内容编辑、图卡规划、素材预览与下载流程：优先从 `src/features/content/ContentPage.jsx` 中抽取可配置的共享区块，再由内容中心传入产品来源和产品事实。
- 内容域交互的实现参考：`src/features/content/useContentWorkspaceActions.js`、`src/features/content/useContentWorkspaceState.js`、`src/features/content/content-options.js`。其中直接依赖选题 ID 和选题 API 的部分不可原样复用，应抽出领域无关的编辑、保存、loading、审核、复制行为，再通过产品中心自己的 API 适配。
- 大模型调用客户端、请求 loading、错误提示、重试交互和生成操作状态；沿用现有模型调用基础设施，但产品摘要和平台稿使用独立提示词、独立输入结构和独立业务 API。
- 草稿编辑/版本操作、人工审核状态、复制工具、通用确认弹窗、Tailwind 布局约定、主题样式和响应式规则。
- 图片生成、图卡计划和 Baoyu 调用能力（是否首期启用产品图文生成待确认）。

实施前应先检查上述实现的当前形态，并形成「直接复用 / 抽成共享组件 / 产品专属新建」清单。需要泛化时优先给现有组件增加明确配置项或领域适配接口，不复制粘贴后分叉维护。产品专属的产品档案、来源引用、产品生成提示词和草稿业务 API 则独立实现。

复用 UI 或基础服务不代表共享业务内容池。产品文案应在产品中心独立查询和维护；如未来需要统一查看，可增加按来源过滤的统一内容视图，而不是把两类草稿混放。

## 8. 数据对象建议

首期可围绕以下实体设计，实际表结构待实施阶段结合现有数据库约定确定：

- `insurance_products`：产品档案。
- `product_documents`：上传文件、资料类型、解析状态和版本信息。
- `product_extractions`：模型解析出的结构化要点、模型信息和待确认项。
- `product_facts`：人工确认后的产品事实及来源引用。
- `product_content_drafts`：平台文案、平台配置快照、审核状态和版本。
- `product_content_versions`：文案历史版本和编辑记录。

每份摘要和草稿必须能够追溯到产品、资料版本、所使用的确认要点及平台配置版本。首期不必引入复杂的通用知识库或向量检索；若文件规模和检索需求增加，再评估切块索引与检索增强生成。

## 9. 后续可拓展路线

### 阶段一：产品资料与平台文案 MVP

- 新增独立产品中心菜单。
- 建立产品档案、上传资料、保存资料版本。
- 提取结构化产品要点，显示出处并支持人工确认。
- 生成知乎、小红书、微信公众号文案，支持平台适配的编辑、预览、审核、版本保存和复制。
- 优先复用大话保险现有的平台预览、编辑、审核和复制能力；必要时先抽成可配置通用组件，再接入产品中心。
- 首期以文本为主；图片生成是否纳入首期由评审决定。

### 阶段二：图文内容和批量编排

- 接入 Baoyu 生成产品解读所需的封面和图卡，图片文字与正文避免重复。
- 同一产品一次生成多平台草稿，允许分别修改和审核。
- 增加产品介绍模板和公司/险种表达规范。

### 阶段三：资料维护与内容复用

- 新旧资料差异比对，标记责任、费率或限制变化可能影响的产品要点和未发布草稿。
- 从确认后的产品事实生成客户版产品说明、常见问题和讲解提纲。
- 为后续智能保单说明书提供产品事实和资料出处。
- 支持批量导入、资料导出、产品停用及历史内容归档。

### 阶段四：业务洞察与个性化辅助

- 记录代理人维护的内容表现数据，比较平台、主题和表达风格效果。
- 基于客户授权信息生成需求问题清单或沟通提纲；由代理人判断，不自动作出承保或适配结论。
- 依据客户已确认需求筛选可进一步讲解的产品，明确展示筛选理由、资料出处和不确定项。
- 增加产品更新提醒、待复核资料和待处理草稿提醒。

## 10. 首期不做的内容

- 自动登录或自动发布到小红书、公众号、知乎。
- AI 自动认定客户适合买某款保险或给出承保结论。
- 未经人工确认直接把模型抽取内容作为权威产品事实。
- 首期建设复杂的产品横向评分、竞品排名或收益推演。
- 把产品推广文案并入「大话保险」通用选题池。

## 11. MVP 验收标准

1. 首期只能创建新华保险产品档案；保险公司和险种使用可扩展字典，后续可启用人保财险等公司和新增险种，无需重构产品档案结构。
2. 上传资料后能看到解析成功、失败或待检查状态，且可关联到具体产品和版本。
3. AI 摘要能区分产品事实、通俗解释、对应需求、保障边界和出处；不确定内容可被标记。
4. 每条已确认产品事实可回到原始资料的页码或章节核对；无可靠来源的内容不会被标成已确认。
5. 知乎、小红书和公众号生成结果在结构、篇幅和语气上有明确区别，不能只替换平台名称。
6. 用户可以编辑、保存历史版本、预览、人工审核并复制文案；内容不会出现在大话保险选题池中。
7. 产品、资料版本、确认要点、平台文案及文案版本之间关系可追踪。
8. 删除产品或资料前展示关联数据数量；确认删除后，按数据关联关系级联删除相关资料、抽取结果、确认要点、草稿和文案版本，不留下孤立业务数据。停用只影响后续选择，不级联删除历史数据。

## 12. 评审时需要确认的决策

1. 首期支持的资料格式是否为 PDF、DOCX、TXT；扫描版 PDF 是否明确放到后续阶段。
2. 首期是否只生成文字，还是同时调用 Baoyu 生成封面和图卡。
3. 产品要点是否必须经人工确认后，才能用于公开平台文案生成。
4. 产品资料更新时，旧草稿和已复制内容是保留原版本引用，还是提示重新生成。
5. 产品中心与「大话保险」保持完全独立的导航和草稿列表；未来是否需要提供统一的跨模块内容查询页。
