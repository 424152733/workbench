# 内容工作台多分类实施方案

**版本：** 1.0（实施方案与代码状态）<br>
**日期：** 2026-10-18<br>
**状态：** 代码已实现；待数据库迁移、API 集成和浏览器验收<br>
**范围：** 将“大话保险”扩展为内容分类工作台，首批支持保险科普、产品解读和客户案例

## 1. 目标与产品决策

目前 `/content` 以“大话保险”作为独立栏目，已有选题、分平台稿件、图卡/配图、审核和发布记录流程。后续内容类型会增加，不应为每一种内容再复制一套编辑页和发布历史。

本方案确定：

- 一级导航和页面名称逐步由“大话保险”调整为“内容工作台”；现有 `/content` 地址保留。
- 页面内部用分类切换，首批分类为“大话保险”“产品解读”“客户案例”。
- 三类内容共用选题、平台稿件、图像素材、审核、发布记录和平台预览能力；分类负责提供写作定位、专属输入、资料来源和审核要求。
- “产品中心”继续维护产品档案、官方文件和已核对的产品事实；公开内容的选题与平台稿件统一在“内容工作台”管理。产品中心提供进入相关内容的链接和新建解读入口。
- 客户案例不直接读取客户 CRM、保单或沟通记录。首期使用人工整理、脱敏后的案例摘要，并在生成/审核前确认授权与脱敏状态。
- 首期分类为内置模板，不提供用户自定义分类管理页。后续增加分类通过新增分类模板、表单和提示词支持；分类元数据采用数据表维护，避免核心选题表为每个分类不断加字段。

本方案调整 [产品中心模块规划](./product-center-plan.md) 中“产品解读内容与大话保险分开管理”的后续产品方向：产品资料仍在产品中心管理，但产品解读的选题、稿件、审核和发布历史进入内容工作台。现有独立产品文案数据应迁入共用工作流，保留原记录可追溯。

## 2. 分类定义

| 分类 | 内容目标 | 创建选题时的专属输入 | 默认来源/审核要求 |
| --- | --- | --- | --- |
| 大话保险 `insurance_education` | 解释保险概念、常见误区和办理事项 | 主题、险种、选题标签、资料来源 | 沿用当前大话保险表达设置和通用审核项 |
| 产品解读 `product_explainer` | 基于具体产品的正式资料说明保障责任、适用条件和限制 | 选择产品档案及已确认的资料提取版本；可补充本篇解读重点 | 只使用产品中心已确认的产品事实；展示所依据的产品/资料版本和核对入口 |
| 客户案例 `customer_case` | 通过案例说明需求判断、保障安排思路和可复用经验 | 案例摘要、需求要点、分析思路、结果/启示、案例性质、授权及脱敏确认 | 不连接 CRM 客户记录；实际案例需确认授权并脱敏，综合/情景案例须显式标注，不能冒充真实个案 |

当前 `topics.category` 表示“保险基础、误区澄清、条款翻译、办事指南”等主题标签；它不是内容分类。本次新增独立 `content_type_code`，继续保留 `category` 和 `insurance_type` 原有含义，避免把现有选题误迁成新类型。

分类模板建议维护以下元信息：稳定代码、中文名称、说明、排序、启用状态、默认发布平台、写作规则键和审核规则键。分类专属逻辑由服务端可测试的规则实现，不允许从数据库配置中执行任意提示词或代码。

## 3. 页面与主要流程

### 3.1 页面结构

- 一级导航显示“内容工作台”，页面标题也使用该名称；面包屑、偏好设置中的起始页选项和通知文案同步调整。
- 在标题下方、统计卡片上方设置分类切换：大话保险、产品解读、客户案例。选中分类后，选题池、统计、创建选题和表达设置均使用当前分类。
- 保留现有稿件编辑器、平台预览、审核操作、图片工作流和发布记录页。编辑器标题/副标题根据分类呈现，不复制整套编辑器。
- 选题列表、内容日历和发布记录筛选均带分类标识。进入发布记录时保留分类筛选；发布记录 URL 继续使用 `view=publications`，分类通过 `type` 参数保留，例如 `/content?view=publications&type=product_explainer`。
- 默认进入 `insurance_education`，兼容 `/content` 现有链接；用户选择分类后同步到地址栏，以支持刷新、分享链接和前进/后退。

### 3.2 新建与编辑选题

创建弹窗根据当前分类显示不同字段：

1. **大话保险：** 沿用当前主题、险种、主题标签、平台和计划日期。
2. **产品解读：** 从产品中心选择产品，再选择该产品下 `已确认` 的资料提取版本。页面展示产品名称、版本/适用日期、事实要点数量、待核对项和资料来源入口。若没有已确认版本，提供“前往产品中心核对资料”的跳转，禁止把未核对资料当成已确认事实生成稿件。
3. **客户案例：** 录入脱敏摘要、保障需求、分析思路、结果/启示和案例性质（经授权的真实案例、脱敏/综合案例、情景示例）。真实案例需确认已取得内容使用授权并完成脱敏；综合或情景示例在生成稿件中明确标为示例，不写成真实客户故事。

三类选题均可选择知乎、小红书、公众号、计划日期和现有主题标签。编辑器展示当前内容分类及必要来源信息。切换分类只改变列表筛选，不会把现有选题改成另一类；已有关联产品/案例的选题应通过明确的编辑表单修改，不能因切换标签而丢失专属信息。

### 3.3 产品中心联动

- 产品档案详情增加“查看内容”和“新建产品解读”入口；新建时带入产品 ID。
- 内容工作台的产品解读编辑区可查看关联产品、资料版本、已确认要点和官方文件名，并链接回产品中心。原文不需要复制进前端表单。
- 对已发布或已审核的产品解读，如果之后产品资料新增版本，旧稿继续显示其原关联版本；不能静默切换到新版本。用户可以新建一篇基于新版本的解读。
- 产品档案仍可独立新增、整理、停用。已有内容引用的产品/资料/提取版本不可硬删除；通过停用或新增版本保留追溯关系。

### 3.4 客户案例保护

- 案例专属表单明确提示不要输入客户姓名、电话、证件号、保单号、精确地址等识别信息；案例无需也不得关联客户 ID。
- 已授权真实案例必须同时确认“授权已确认”和“身份信息已脱敏”后才可生成；审核通过前再次展示两项确认状态。
- 综合/情景示例必须在选题和正文中清楚标识“综合案例/情景示例”，不得由模型补写真实姓名、真实理赔经过、具体产品责任或金额。
- 仅存储完成编辑所必需的案例摘要，不上传或复制同意书、身份证明、客户档案或保单原件到内容流程。
- 生成、审核仍为人工负责；工作台不自动发布，也不把模型生成视为合规审查。

## 4. 生成、审核与发布规则

### 4.1 生成

将提示词组织为“通用保险内容规则 + 内容分类规则 + 平台规则 + 本篇资料”。共用事实准确、语言清晰、来源可追溯、说明适用边界等要求；每个分类明确写作目标：

- 大话保险沿用当前保险科普与误区澄清规则。
- 产品解读仅以所选 `product_extractions.status='已确认'` 的事实和其来源文件为材料；明确产品版本、适用范围、责任限制、免责和需要核实项，不承诺收益/赔付，不把单品介绍写成适合所有人的建议。
- 客户案例仅以用户提交的脱敏摘要为材料；不补造人物细节、保费/保额、理赔结果和客户评价；缺失事实保持为空或说明无法确认；示例性质必须显式保留。

Humanizer 只改善表达，不得改变事实、来源、授权/脱敏标识和保险边界。Baoyu 图片工作流继续使用已审核的平台稿件/图卡规划，不从真实客户资料生成包含个人身份信息的图片。所有文本与图片生成仍由现有配置控制；实施和测试使用 mock，不调用真实付费模型。

小红书各分类共用中等信息密度的图卡标准：封面以 1–2 条短句补充主题；解释卡建议 2–3 条约 20–35 字的完整短句，让读者在不看长段正文的情况下理解要点。每张要点约 50–90 字为宜，简单内容可以更短，不重复凑字；图像布局完整呈现已审核要点，避免压缩成关键词或堆成大段正文。

### 4.2 审核

保留现有三项通用审核，并按分类追加必需检查：

- 产品解读：产品名称和版本一致；责任、期限、条件及除外责任与官方资料一致；关键表述可以回到资料来源核对。
- 客户案例：授权状态符合案例性质；文本和图片均已脱敏；真实事实与假设/综合内容有清晰区分。

服务端在审批接口校验分类专属审核项和关联状态，不能仅依赖前端 checkbox。修改产品关联、产品提取版本、案例摘要或稿件正文后清空对应审核状态。发布登记仍按当前发布记录规则手动进行；发布快照额外保存内容分类、关联产品/资料版本或经审核的案例性质标识。

## 5. 数据结构与迁移

使用事务迁移 `backend/migrations/009_content_workspace_categories.sql`。不要把新业务结构放入每次启动都执行的 `schema.sql`。迁移通过启动时的 `schema_migrations` 记录只执行一次；SQL 使用冲突保护并在尾部核对旧稿和旧版本数量，事务失败会回滚。执行迁移前仍需在一次性数据库副本验证。

| 结构 | 设计 | 用途 |
| --- | --- | --- |
| `content_types` | `code` 主键、`name`、`description`、`sort_order`、`active`、`default_platforms JSONB`、`prompt_key`、`review_key` | 首批插入三类；元信息可扩展，但具体模板仍由代码实现和测试 |
| `topics.content_type_code` | 非空，外键到 `content_types`；旧数据回填 `insurance_education` | 分类与现有 `topics.category` 主题标签分离 |
| `content_topic_products` | `topic_id`、`product_id`、`extraction_id`、`source_snapshot JSONB`；外键限制删除被引用产品/提取版本 | 记录产品解读关联。首期 UI 只允许一个主产品；快照保留当次使用的事实及来源标识 |
| `content_topic_cases` | `topic_id` 主键、脱敏摘要及需求/分析/结果字段、`case_kind`、授权和脱敏确认布尔值、创建/更新时间 | 单独维护客户案例输入，不给客户 ID，不保存同意书或原始客户档案 |
| `content_publications.content_type_code` | 新增发布分类列，旧记录默认 `insurance_education`；稿件快照另保存分类和来源上下文 | 发布记录按登记时分类筛选；分类及产品/案例来源留在发布快照中 |
| `product_copy_draft_migration_map` | `legacy_draft_id`、`content_draft_id` 唯一映射 | 让旧产品中心文案迁移可追溯、迁移检查可重复验证 |

产品与提取版本的组合必须经数据库外键或服务端事务校验，避免把产品 A 的提取版本挂到产品 B。产品资料版本快照至少包含产品 ID/名称/版本、提取记录 ID、确认时间、已确认事实、来源文件 ID/名称与待核对项；生成时从数据库读取，不接受浏览器伪造的事实快照。

### 5.1 既有数据迁移

- 既有所有 `topics` 都标为 `insurance_education`；原 `category`、`insurance_type`、稿件、图卡、图片、计划日期和发布记录均保留。
- 对每个存在 `product_copy_drafts` 的 `product_extractions` 创建一个 `product_explainer` 内容选题，并关联原产品和提取版本；把其平台文案迁入同一个内容选题的 `drafts`。沿用标题、摘要、正文、标签、来源、HTML、审核状态、审核检查和平台字段。每条旧文案记录写入迁移映射表。
- 将 `product_copy_versions` 迁入共用稿件版本表；在快照中附加原产品配置快照。历史记录仍可查看和恢复，恢复后按共用稿件规则重新审核。
- 旧产品文案没有客户案例数据，不创建客户案例选题。旧稿缺少小红书图卡规划时保留空规划，并按现有旧稿提示补齐，不推测图卡。
- 迁移后产品中心旧“平台文案”入口改为查看对应内容工作台选题；旧表先只读保留一个版本周期，不在迁移当下删除原数据。迁移核对通过后，后续单独评估何时清理旧表。
- 重复执行迁移或重启 API 不得新增重复选题、稿件、素材或版本。逐类核对源文案数与迁移映射数，异常行阻止迁移并报告，不能静默跳过。

## 6. 接口与代码落点

### 后端

- `backend/content-operations.js`：选题列表按分类筛选；创建/更新选题时校验分类字段；产品和案例专属输入以事务保存；生成、审核、提示词和发布快照按分类执行规则。
- `backend/product-center-operations.js`：继续负责产品、资料、事实提取；增加可供内容工作台调用的已确认资料上下文和相关内容查询；删除被关联的资料/提取/产品时返回可理解的冲突。
- `backend/publication-operations.js`：查询支持 `contentType`；发布快照保存内容分类和来源上下文，不把用户未选择的产品或图片带入快照。
- `backend/api.controller.js`、`backend/workbench.service.js`：控制器只做参数转发；使用 WorkbenchService 门面维护同一数据库/事务上下文。增加分类列表/元数据读取接口，并扩展 topics、产品关联和案例输入接口。
- `backend/content-prompts.js` 与 `backend/product-center-prompts.js`：抽取可复用的产品事实提示词片段，避免产品中心和内容工作台维护两套相互漂移的文案规则；所有 prompt builder 以纯函数测试。
- `backend/test/`：覆盖分类默认值、非法分类、产品关联完整性、提取状态、客户授权/脱敏、审批门禁、发布快照、迁移映射与幂等性。

建议 API 契约：

| 接口 | 用途 |
| --- | --- |
| `GET /api/content/types` | 返回启用分类及展示元数据 |
| `GET /api/topics?type=product_explainer` | 按分类读取共用选题及稿件 |
| `POST /api/topics` | 接收 `contentTypeCode` 与对应分类字段；服务端验证后创建 |
| `PATCH /api/topics/:id` | 更新主题/分类专属输入；有发布记录时禁止改变历史分类 |
| `GET /api/product-center/products/:id` | 复用现有产品工作区读取产品资料；响应中提供可选的已确认提取版本 |
| `GET /api/publications?type=customer_case` | 按发布时分类筛选历史 |

产品事实可以由 `POST /api/topics` 创建时在服务端按产品/提取 ID 读取；首期不需要再提供任意事实导入接口。客户案例摘要仅接受显式字段和长度上限，不接受 CRM 客户 ID。

### 前端

- 新建 `src/features/content/` 下的分类切换、分类专属选题表单和产品/案例上下文组件；`ContentPage.jsx` 组合页面，不把分类表单状态堆进 `App.jsx`。
- 分类与 `view=publications` 查询参数通过 `navigation.js` 同步，直接打开、刷新、前进/后退可恢复。
- 更新 `src/api.js`、选题创建弹窗、内容日历、发布记录列表及产品中心入口。加载、保存、生成、审核、关联产品版本失败均展示可读错误并防止重复提交。
- 沿用现有 Ant Design、明暗主题、窄屏规则、平台预览和图片下载/删除行为。
- 通知、偏好设置起始页、导航标题和页面 breadcrumb 中的旧栏目名称统一替换；旧 URL 与旧收藏链接仍可用。

## 7. 实施顺序

1. **数据盘点和迁移演练：** 在一次性数据库副本统计现有主题、产品提取、产品平台文案、稿件版本和发布记录；先完成 009 迁移草案及反复执行测试。
2. **分类基础层：** 分类元数据、`content_type_code`、分类查询参数、旧选题默认归类、导航和页面分类切换。
3. **共享产品解读：** 将产品中心现有文案迁入通用稿件；新建产品解读从已确认产品事实生成；产品中心入口跳转至共用选题；旧编辑入口改为只读/跳转。
4. **客户案例：** 实现案例摘要表单、案例性质、授权/脱敏门禁、专属生成规则和审核项；不接 CRM 数据。
5. **发布和统计：** 发布历史按分类筛选与显示快照分类；各分类统计单独计算，现有首页/大话保险相关数字口径不被意外改变。
6. **体验和文档收尾：** 检查窄屏、暗色主题、加载/错误、路由恢复和数据迁移结果；更新实施记录及验证报告。

当前代码已在同一交付批次包含分类基础层、产品解读迁移和客户案例隐私门禁；上线前仍需使用一次性数据库副本完成迁移演练和 API 集成验收。

## 8. 验收标准

1. `/content` 默认显示大话保险；可在同一页面切换三类内容，地址栏、刷新及浏览器前进/后退保持选择；页面不新增一级侧栏入口。
2. 原大话保险选题、草稿、图片、图卡、审核状态、内容日历和发布记录继续可用，旧数据全部归类为 `insurance_education`。
3. 已确认产品资料可在内容工作台创建产品解读；产品名称、版本、事实及来源准确关联，稿件不能把未确认/跨产品事实作为已核实内容生成；产品档案详情可以打开其相关共用选题。
4. 产品中心现有平台文案迁移后，在内容工作台可继续编辑、查看版本并审核；迁移计数与源记录一致，原表保留只读，二次执行不重复迁移。
5. 客户案例不能引用客户 CRM ID。实际案例未确认授权或未确认脱敏时，服务端拒绝生成/审核；综合/情景案例在编辑器和发布历史中可见其性质标识。
6. 产品解读和客户案例继续使用同一平台草稿、预览、图像、审核、发布登记和历史详情，不产生第二份发布历史。
7. 发布记录按登记时的分类筛选；详情快照保留当时产品/资料版本或案例性质；更正稿件分类不改写历史分类。
8. 服务端校验抵御非法分类、产品和提取版本不匹配、删除被引用来源、重复提交和缺少案例确认；数据库事务失败时不留下半条记录。
9. `npm run build` 和 `npm run test:ui-logic` 通过；API 集成测试使用一次性可丢弃 PostgreSQL 数据库运行。浏览器验证涵盖三类创建/编辑、发布历史、刷新、窄屏、明暗主题和错误状态。
10. 自动化验证不调用真实 GPT、Humanizer、Baoyu 或 Runware；不调用社交平台发布接口。

## 9. 风险与处理

- **旧产品稿件迁移造成丢失或重复：** 先在一次性副本演练；迁移映射、事务和源/目标数量校验齐备后再部署。源表保留只读，确认后续备份周期再评估清理。
- **产品事实更新导致旧稿来源漂移：** 保存所选已确认提取版本及其事实/文件名快照；产品资料版本更新不覆盖现有草稿的来源。
- **案例泄露客户身份：** 不接 CRM、不存客户 ID，表单做明确提示并限制输入；服务端门禁要求确认授权和脱敏。模型不能作为脱敏工具或事实审核工具。
- **分类规则膨胀：** 共用平台编辑、审核、图片和发布组件；只有真正不同的表单、提示词和审核规则按分类扩展，避免复制页面。
- **历史发布信息不可追溯：** 新发布记录保存分类快照；已经迁移的旧发布记录统一归入大话保险，因为此前工作流只有该栏目，不能凭标题推断其他类别。
