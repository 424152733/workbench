# 家庭保单整理与保障检视实施方案

**状态：** 首版已实施；具体实现和验证见 `family-policy-review-implementation.md`。<br>
**范围：** 客户与保单模块的家庭工作区、合同归属、保障检视和 Excel 导出。保留现有个人页面及其数据。

## 1. 目标与首版交付

从 `/families/:familyId` 进入家庭保单整理。业务员可把家庭成员名下的已归档保单和未归档 PDF 合同纳入同一家庭，明确每份合同的投保人、被保险人及资料状态，然后得到：

1. 家庭概览：成员数、已纳入合同数、已识别的年交保费、待核对及已过期合同数。
2. 成员保障：逐人查看医疗、重疾、身故、意外、年金责任及来源合同；展示可确认金额、待核对金额和给付条件。
3. 家庭服务重点：先看每人的医疗保障，再看主要收入承担者的身故兜底，最后看养老、教育等长期现金流安排；每条提示给出依据、待确认信息和下一步沟通动作。
4. 家庭 Excel：与个人版共用单张“家庭保单整理”模板、提取与统计规则；成员行数动态扩展，保险责任在同一张表中展开。

首版不计算一个“家庭总保额”，不依据缺少的收入、负债或合同状态编造目标保额，也不自动推荐具体产品。个人版继续可独立使用；家庭页只引用已有客户和合同，不复制原始 PDF。

## 2. 现有基础与真正缺口

| 已有能力 | 需要补齐 |
| --- | --- |
| `families`、`family_members`、关系及 `family_policies`；家庭保单可关联投保人和被保险人 | 未归档 PDF 合同无法显式纳入家庭，也无法把被保险人可靠绑定到家庭成员 ID |
| `FamilyPolicyDiagnosis` 显示已关联保单的分类和状态 | 尚未读取个人保障检视中的责任、金额、来源页码及服务重点 |
| `customerCoverageReview` 和 `buildCoverageReview` 支持单客户多保单与未归档合同 | 按客户 ID 取数，个人归属部分依赖姓名；不能直接当作家庭汇总 |
| `exportPolicyOrganizer` 导出单客户保单 | 查询范围仍为一个客户，概览最多显示三名被保险人；不能直接作为家庭导出 |
| `customer_coverage_profiles` 记录个人医保、收入责任等信息 | 简要家庭成员没有客户档案；家庭层面的主要收入者、抚养责任和长期目标尚未确认 |

原家庭初筛面板已由家庭保单整理与保障检视替换；旧分类标签不直接当作合同责任金额。

## 3. 数据归属与去重

### 3.1 来源和成员

- `policies.customer_id`、`customer_policy_contracts.customer_id` 继续表示资料所在的客户档案；家庭归属另行显式确认。家庭成员使用 `family_members.id`，不能仅凭姓名匹配。投保人与被保险人分别关联；被保险人未确认的合同放入“待分配”，不计入任何成员的已确认保障。
- 一份合同可以由家庭中一位已建档客户上传，也可以保障一位只有简要成员记录的家人。家庭上传入口先选择资料所属客户，默认主要服务联系人；上传后指定被保险成员。保留合同原文中的姓名供人工核对。
- 增加版本化迁移，建立 `family_contracts(family_id, contract_id, created_at)` 和 `family_contract_people(family_id, contract_id, member_id, role)`；角色先支持投保人、被保险人。前者以家庭 ID + 合同 ID 为主键，后者以家庭 ID + 合同 ID + 成员 ID + 角色为主键；两表采用明确外键和级联规则，关联前校验合同所属客户已是该家庭的已建档成员。未分配成员的合同可存在于 `family_contracts`，但只能显示在待核对区。
- 已有 `family_policy_people` 继续服务归档保单。合同归档时在同一事务中保留家庭关联并补齐相应的 `family_policies` / 人员角色；归档保单和原 PDF 在检视中归并为**一份保单、一个来源键**，PDF 作为责任证据。无法唯一匹配的旧合同只列候选，不自动关联或合并。
- 删除或移出家庭的合同不再进入家庭统计；删除保单时遵循已有 `coverage_excluded_at` 规则。删除家庭成员后，相关合同转为“被保险人待确认”，不能默默转给其他成员。

### 3.2 资料状态

- 仅“人工核实 + 合同有效 + 已确认被保险人”的责任进入**已确认当前保障**。
- 未归档 PDF、状态未知、待生效、过期、终止和解析不完整的记录保留在**待核对/非在保**，其可辨金额只作为参考，不并入已确认金额。到期但可能续保的合同必须先取得续保或当前在保证据。
- 已归档保单与关联 PDF 以保单 ID 去重；未归档合同以合同 ID 去重。同一份合同多项责任可以分别展示，但同一年度共用医疗限额不得重复求和。
- 金额使用统一结构：数值、币种、单位、口径（基本保额/年度限额/日额/未来领取等）、责任条件、来源及页码、核实状态。由现有合同事实和责任解析器生成，允许人工修正；分类判断和汇总在本地确定性执行，不为家庭视图再次调用付费模型。

### 3.3 家庭需求资料

- 已建档成员读取现有 `customer_coverage_profiles`；简要成员的医保等个人资料保存在新增的 `family_member_coverage_profiles(family_id, member_id, profile_data, updated_at)`，以家庭 ID + 成员 ID 为主键。简要成员转为客户时先展示两个来源供确认，不自动覆盖客户档案。
- 新增最小的 `family_coverage_context(family_id, context_data, updated_at)`，以家庭 ID 为主键；其中记录经确认的主要收入承担成员 ID、经济依赖成员 ID、家庭负债是否存在、养老/教育目标。个人资料中的收入责任可作为候选，不自动决定家庭角色。
- 缺少收入、负债余额、必要支出或责任年限时只提示需要补问，不计算“应配置多少万”的目标保额。

## 4. 统计与建议口径

| 视图 | 规则 |
| --- | --- |
| 家庭保费 | 同一保单只算一次；仅把缴费频率明确且当前仍需缴费的金额计入“已识别年交保费”。趸交、已缴清和待核实保费另列。该数字是家庭所纳入保单的缴费额，不直接等于家庭实际现金支出；付款人未核实不据此推断家庭付款。 |
| 成员医疗 | 每人独立看医保、单位福利、住院报销、门急诊、免赔额、赔付比例和续保；不同合同年度限额可并列，合同内共用上限不得将分项相加。 |
| 成员重疾 | 按合同基本保额及给付条件逐人列示；多次给付、附加关爱金单列，不作为无条件基本保额。 |
| 身故与意外身价 | 按**被保险人**列示。普通身故责任若覆盖意外身故，可同时出现在两个视角，但标明同源重叠，不能跨列相加；既往理赔扣减和限期附加给付单列。 |
| 意外医疗与津贴 | 只有独立可识别的责任金额才汇总；一般医疗含意外诱因不自动变成独立意外门急诊。每日津贴与一次性给付分开。 |
| 增额终身寿与年金 | 保证身故责任、现金价值、年金领取和非保证分红分开；不将未来领取总额算作当前保障。 |
| 家庭判断 | 先形成逐人结论，再汇成家庭服务顺序。成员之间不合并保额；“档案没有记录”只能提示核实，不能断言现实中没有保障。 |

服务重点由现有个人规则扩展，但必须附上成员、触发事实、来源和不确定性。例如主要收入承担者有经济依赖成员而有效身故责任尚待核实，提示“核对家庭兜底安排”，并列出应确认的保单状态、收入责任与负债资料。支持转为现有跟进待办，不自动创建。

## 5. 页面与接口

### 页面

`FamilyWorkspacePage` 新增“保单整理与保障检视”区域，页面组件只组合领域组件：

1. 顶部显示家庭保单摘要与“上传合同 / 关联已有保单 / 导出家庭整理表”。
2. 成员矩阵按行显示每位被保险人，按列显示医疗、重疾、身故、意外和年金；单元格为“已确认 / 待核对 / 暂无档案记录”，点击展开金额、合同和条件。
3. “待分配与待核对”集中显示 PDF、保单状态、被保险人和来源冲突，提供人工归属操作。
4. “家庭服务重点”只放可行动的简短卡片；点击可查看依据及安排跟进。
5. 宽屏使用矩阵和侧栏；窄屏改成员卡片。保持明暗主题、请求 loading、重复提交拦截、错误提示及直接刷新路由可恢复。

新增组件放在 `src/features/customers/`，计算逻辑放纯函数；不把家庭版整页状态堆到 `src/App.jsx`。

### 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/families/:familyId/policy-review` | 一次返回成员、纳入来源、逐人分类、家庭服务重点与资料状态 |
| `GET /api/families/:familyId/policy-contract-candidates` | 列出家庭已建档成员名下可纳入但尚未关联的 PDF |
| `POST /api/families/:familyId/policy-contracts` | 复用现有本地 PDF 上传/解析，指定资料所属客户和成员归属；链接失败时清理本次新文件 |
| `PUT /api/families/:familyId/policy-contracts/:contractId` | 纳入合同及确认投保人/被保险人；参数和家庭成员归属在同一事务校验 |
| `DELETE /api/families/:familyId/policy-contracts/:contractId` | 仅从家庭移除，不删除客户原合同 |
| `PUT /api/families/:familyId/coverage-context` | 保存家庭收入责任、依赖关系和长期目标 |
| `GET /api/families/:familyId/policy-organizer/export` | 导出家庭 Excel，保留当前个人导出接口 |

简要成员的资料更新可在现有家庭成员接口中增加受限的保障资料字段，或单设 `PUT /families/:familyId/members/:memberId/coverage-profile`；实施时选一处，避免两个写入入口。

后端在独立的家庭保单领域操作中组装数据，经 `WorkbenchService` 门面共用数据库上下文；从个人整理和检视提取可复用的来源归并、状态判定、责任金额与分类纯函数。控制器只接参数和响应。新增接口同时更新 `src/api.js`。

## 6. Excel 结构

1. **家庭保单整理：** 沿用个人版标题、样式和字段。家庭成员逐行列示分类保障金额；成员行不限三人。下方每份关联保单列出投保人、被保险人、产品、起止日、缴费；同一保单及其 PDF 不重复。
2. **保险责任：** 所有责任及不同给付情形都在第一张表的“保险责任”列展示，列明金额或公式、限额、条件和责任关系；原 PDF 页码留在内部核验信息，不占用客户阅读的责任文字。每份保单固定一行，长内容保存在同一单元格。多人共用限额及归属未确认的合同保留在保单列表中，不直接计入个人金额。

导出只选择当前家庭已关联的来源，并复用个人版的合同提取、字段格式化和工作簿生成器。文件名含家庭名称与整理日期；个人导出维持现有入口。可识别但尚未核实有效的金额可按状态显示，并明确标注待核或原保期已过；无法识别金额保持空白，不能以 0 伪装成没有保障。

## 7. 实施顺序与验收

| 阶段 | 工作 | 完成标准 |
| --- | --- | --- |
| A. 统一事实与口径 | 抽取个人版和家庭版共享的合同去重、状态、责任分类及金额计算；补纯函数测试 | 同一来源得到相同的基础事实与状态；家庭版明确区分已确认和待核对，个人导出本阶段保留现有布局与展示口径；没有真实模型调用 |
| B. 家庭合同关联 | 版本化迁移、候选接口、上传和人工确认归属；归档与删除联动 | 合同可指定简要成员为被保险人；归档后不重复；移除关联不删客户资料 |
| C. 家庭检视与建议 | 家庭 API、成员矩阵、待核对和服务重点；复用个人保障资料 | 每条金额能追溯至一份合同/责任；资料不足不生成确定性缺口结论 |
| D. 家庭 Excel | 动态概览、去重保单及责任明细 | 多于三名成员也能完整导出，页内金额与页面一致 |

**关键场景：** 一位家长投保、孩子为被保险人；同一合同有原 PDF 和已归档保单；同一客户加入两个家庭；同名成员；未归档合同、过期医疗险、停效/待核实保单；一般与特定医疗共享上限；重疾险身故责任同时覆盖意外；趸交和年缴混合；删除保单或 PDF 后刷新页面和导出。用合成资料验证逻辑；API 集成测试只在一次性测试数据库运行，不碰实际客户库。

实施完成后运行构建、相关纯逻辑和 API 测试，并在浏览器核对家庭路由刷新、上传/归属/移除、导出、窄屏和明暗主题。验收时用客户授权的实际合同对照原文抽查，但不运行付费 AI 以制造测试资料。
