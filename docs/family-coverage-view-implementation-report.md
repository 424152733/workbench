# 家庭规划模块首版实施报告

**日期：** 2026-10-17  
**范围：** 家庭关系与保障底座；不含家庭财务台账、资产估值、风险评分、方案测算或外部账户接入。

## 已实现

- “客户与保单”新增“家庭规划”列表，可搜索、创建和删除家庭。
- 家庭与客户详情使用独立地址；客户从家庭成员进入详情后，可经面包屑或返回按钮回到该家庭。
- 家庭支持已有客户与简要成员；选择已有客户后会清除简要称呼并以客户档案姓名展示，避免两种身份同时提交；成员关系可添加、编辑和解除，关系两端由服务端校验。
- 家庭关系画布使用 SVG 绘制关系线、HTML 卡片呈现成员，显示姓名、成员身份和客户阶段；头像暂用姓名首字作为圆形占位。已确认的配偶、亲子、兄弟姐妹和其他关系通过带文字标签的连线展示。亲子连线从关系 A（父母）指向关系 B（子女），线尾显示箭头；标签按节点的实际相对位置同步显示左右或上下方向。自动布局按代际分行，父母在上、子女在下，并尽量让父母与其子女垂直对齐；同代兄弟姐妹相邻排列。成员不超过 6 位时使用直线关系连线，人数更多时使用弧线降低拥挤。画布高度按实际布局行数计算。节点可在画布内拖动，连线随节点同步更新；“适应画布”恢复自动布局。成员卡片继续联动右侧客户信息，关系标签可打开关系编辑。家庭保单的归属操作单独成行并右对齐，按钮距操作区边缘 16px。详情页采用两列瀑布流，左列依次放置家庭关系、已确认关系和家庭保单，右列依次放置成员信息、财产保障和服务事项。
- 家庭列表的搜索框左对齐，“建立家庭”按钮与搜索框同行；详情页通过面包屑返回家庭规划，不再重复显示底部返回按钮。
- 添加家庭成员与关联客户的选择器打开时展示最近更新的 20 条客户档案，继续输入姓名或电话可搜索；本家庭已有成员会从候选中排除，接口始终限制最多 20 条，不会加载全量客户表。
- 家庭支持房屋、车辆等投保对象，以及已有保单的投保人、被保险人、投保对象和家庭保障分类关联；家庭归属编辑和解绑都有独立操作。
- 家庭详情显示保单核实状态及开放服务事项；删除家庭只删除家庭关系和关联，不删除客户/保单原始档案。
- SQL 使用版本迁移，保障分类按家庭保单关系保存，避免同一保单在多个家庭之间相互覆盖。
- 客户检索接口将静态 `/customers/lookup` 路由排在 `/:id` 前；空搜索返回最多 20 条最近更新的客户档案，避免把 `lookup` 当作客户编号。

- `npm run build`：通过。Vite 提示存在大于 500 KB 的共享 chunk，构建未失败。
- `npm run test:ui-logic`：18 项通过，覆盖动态路由、家庭返回上下文、家庭成员身份提交规则、关系图节点/连线布局及亲子方向标签。
- `npm run build` 与 `npm run test:ui-logic`：本次界面调整后再次通过；构建仍有共享 chunk 大于 500 KB 的提示。
- 浏览器桌面检查：家庭列表工具栏、家庭详情圆形节点、成员操作区、客户检索弹窗均已查看。最新布局复查确认家庭保单接在左列、服务事项接在右列；两列外边距、列宽和列间距一致，空状态下卡片也按各自列连续排列。窄屏与深色主题未在本次复查。
- 浏览器发现原 relation-graph 集成的内部画布始终为 300×300，关系线 SVG 高度为 0，拖动时还因画布 DOM 引用为空报错；现已改为同一坐标系下的 SVG 关系线和可拖动卡片。
- 客户选择器默认候选修复后，定向后端操作与路由测试、前端逻辑测试及构建通过；浏览器打开新增成员弹窗后可直接看到可关联客户候选。
- 后端无数据库单元测试：59 项通过，含跨家庭关系校验、客户搜索、简要成员关联已有客户、家庭级保障分类保存。
- `node --check`：家庭操作、API 控制器与服务门面语法检查通过。
- 本次修复后，客户检索相关定向测试 6 项通过；包含无数据库的 NestJS HTTP 路由回归测试。
