# 大话保险发布记录实施方案

**版本：** 1.1（已实施）  
**日期：** 2026-10-18  
**范围：** 大话保险的人工发布登记、历史查询和记录更正

## 1. 目标与口径

顾问在知乎、小红书或公众号完成站外发布后，可以在工作台登记一次发布，并在“发布记录”中按时间查看：发布了哪篇、发到哪个平台、实际发布日期、发布链接，以及登记时留存的稿件与配图。一次实际发布对应一条记录；同一选题在三个平台发布有三条记录，同一平台再次发布也保留新的一条。记录更正和作废留痕。

本模块只记录顾问手动确认的站外发布，不调用平台发布接口，也不将“已审核”自动视为“已发布”。“本月已发布 X 篇”按当月有有效发布记录的不同平台稿件数统计；同一稿件当月多次发布仍算一篇。发布记录列表则逐次展示每一次发布。

## 2. 当前实现与缺口

| 当前能力 | 实际行为 | 需要补足 |
| --- | --- | --- |
| 稿件发布登记 | `POST /api/topics/:id/drafts/:platform/publish` 把 `drafts.status` 改成“已发布”，并更新同一行的 `published_at`、`publish_url` | 再次登记会覆盖原日期和链接；改为每次写一条发布记录 |
| “更新发布记录”弹窗 | 只填写日期、可选链接；提交后更新当前稿件 | 区分“再次登记发布”与“更正已有记录”，避免误覆盖 |
| 稿件版本 | `draft_versions` 在编辑前保存快照 | 不保证发布当时有版本，也没有图片集合快照；发布时单独留存 |
| 内容日历 | 按 `topics.due_date` 显示排期选题 | 保持排期含义；发布历史用独立视图展示 |
| 本月已发布 | 按当前 `drafts.status='已发布'` 和 `published_at` 统计 | 改从有效发布记录统计，避免稿件后续编辑后历史消失 |

当前代码落点：`backend/content-operations.js`、`backend/schema.sql`、`backend/customer-followup-operations.js`、`src/features/content/ContentPage.jsx`、`src/features/content/ContentOverlays.jsx`。现有稿件编辑会在内容变化后把工作稿状态退回“草稿”；过去的发布记录应继续保留，不随工作稿状态变化。

## 3. 页面与操作流程

在“大话保险”顶部增加“内容工作台 / 发布记录”视图切换。发布记录地址为 `/content?view=publications`，刷新、复制链接及浏览器前进后退都可恢复。现有内容日历继续显示排期，不与发布记录混用。

1. **登记发布：** 已审核或已发布的当前平台稿件显示“记录已发布”；点击后默认选择北京时间今天，可改实际发布日期、可选具体时间、发布链接和备注。链接可稍后补录。表单明确说明这是人工登记，不会向平台发文。提交时可选择本次实际使用的配图，默认勾选当前平台预览中的图片。若编辑器还有未保存变更，先完成保存并重新核对审核状态，再允许登记。保存成功后进入本篇历史，当前工作稿显示“已发布”。
2. **再次发布：** 同一稿件再次发出时使用“新增一条发布记录”；不预填上一条的链接，以免把旧地址记成新地址。网络重试凭请求标识只产生一条。若日期、平台和链接与已有有效记录完全相同，先提示可能重复，并可明确选择继续登记。
3. **历史列表：** 默认按实际发布日期倒序、同日按记录 ID 倒序分页。提供平台、日期范围、选题/标题关键词筛选；每行显示标题、平台、日期、链接状态、记录来源。桌面用表格，窄屏用卡片。点击本月已发布数字可打开当月筛选结果。
4. **记录详情：** 展示发布信息、登记时间、当时留存的工作台标题/正文/平台字段、已选配图、外部链接，以及后续更正/作废时间线。外部链接以新窗口打开，使用安全的 `rel` 属性。快照标明是“登记时工作台稿件”，不声称与平台上最终内容逐字一致。
5. **更正与作废：** 在记录详情中更正日期、时间、链接或备注时必须填写原因，保留改前/改后的事件；不允许通过更正改写已留存稿件正文。误登记可“作废”并填写原因，历史仍可查看，默认列表和统计不包含作废记录。必要时可筛选查看作废项。

空列表提示“还没有发布记录”，并提供返回已审核稿件的入口。列表加载、保存、更正、作废均显示 loading、阻止重复提交，失败时保留表单并显示可读错误。沿用现有明亮/黑暗主题和按钮样式约定。

## 4. 数据结构与保留规则

使用下一版迁移 `backend/migrations/008_content_publications.sql` 创建以下表与索引；不把新结构或回填语句继续塞入启动时重复执行的 `backend/schema.sql`。`DatabaseService` 现有迁移执行器会在事务中按版本执行，并使用数据库锁串行化。

| 数据 | 关键字段与约束 | 用途 |
| --- | --- | --- |
| `content_publications` | `id`；`draft_id BIGINT REFERENCES drafts(id) ON DELETE RESTRICT`；`platform`；`topic_title_snapshot`、`title_snapshot`；`published_on DATE NOT NULL`；可空的 `published_time TIME`、`publish_url`、`note`、`content_snapshot JSONB`；`status` 为 `active/voided`；`origin` 为 `manual/legacy`；`request_key UUID UNIQUE`；`recorded_at`、`updated_at`、`voided_at` | 一行代表一次实际发布。日期与录入时间分别保存，避免把“今天补录”误当发布日期。 |
| `content_publication_assets` | `publication_id`、`asset_id REFERENCES assets(id) ON DELETE RESTRICT`、`position`、`file_name_snapshot`；对同条记录的顺序与资产 ID 建唯一约束 | 固定本次登记使用的图片及顺序，后续生成/上传新图不改变旧记录。 |
| `content_publication_events` | `publication_id`、`action`（`created/corrected/voided`）、改前/改后值、原因、`request_key UUID UNIQUE`、`created_at` | 保留人工更正和作废的操作历史，重试不重复写事件。 |

`content_snapshot` 在登记事务内从数据库当前稿件读取并保存：标题、摘要、正文、话题标签、资料来源、小红书图卡规划及公众号 HTML。前端提交的稿件正文不作为快照来源。旧稿无法还原发布当时内容时，此字段为 `NULL`，详情明确显示“历史稿件内容不可追溯”。图片不复制进 JSON，按关联的资产记录读取；既有素材文件应随发布记录保留。

建立 `(published_on DESC,id DESC)`、`(platform,published_on DESC,id DESC)`、`(draft_id,published_on DESC,id DESC)` 索引。列表只返回摘要和计数，详情才读取正文快照和配图，避免整页传输大文本。所有 SQL 使用参数化查询。

现有删除选题会级联删除稿件、资产与本地文件。为了保住发布历史，本期在服务层对已有发布记录的选题拒绝硬删除并返回可读的冲突提示；外键同时提供最后一道保护。没有发布记录的选题维持原删除流程。以后若增加素材清理，也必须跳过被发布记录引用的文件。已发布选题的归档/隐藏可在后续增加，不能用硬删除绕过历史保留。

## 5. 旧数据迁移

迁移对 `drafts.published_at IS NOT NULL` 的每个稿件最多生成一条 `origin='legacy'` 记录，日期按 `Asia/Shanghai` 转成 `published_on`，链接沿用 `publish_url`。包括后来又被编辑为“草稿”的稿件，因为它们仍可能保留旧发布日期。用部分唯一索引或等效约束保证同一稿件不会重复回填；迁移重跑和 API 重启不得再次增加记录。

旧结构只保存最后一次日期和链接，**无法恢复更早的多次发布**。旧记录的 `content_snapshot` 留空、图片关联留空，并在页面标记“旧数据导入：仅日期与链接可确认”。不能把当前可编辑稿件或当前全部图片伪装成当时发布的内容。若存在 `status='已发布'` 但 `published_at IS NULL` 的异常稿件，输出待人工核对数量，不猜测日期、不自动创建发布记录。

迁移前在一次性数据库副本核对：原始有发布日期的稿件数、导入的旧记录数、原有稿件/素材数；迁移后重复启动，再核对数量不变。保留 `drafts.published_at/publish_url` 作为兼容投影；创建、更正或作废后，按实际发布日期、可选时间和记录 ID 取最新有效记录重算，全部作废时置空。仅有日期的记录映射为北京时间当天起点，界面不得把这个兼容时间戳称为准确发布时间。列表与统计不再读取这两个字段。

## 6. 接口与事务规则

| 接口 | 行为 |
| --- | --- |
| `POST /api/topics/:id/drafts/:platform/publish` | 保留现有地址，升级为“新增一次发布”。接收 `publishedOn`、可选 `publishedTime/publishUrl/note/assetIds` 和必填 `requestKey`；返回 `{draft, publication}`。新客户端同步更新 `src/api.js` 与调用方。 |
| `GET /api/publications` | 按 `platform/from/to/topicId/keyword/status/page/pageSize` 分页查询摘要，返回 `items/total/page/pageSize`。默认只看有效记录。 |
| `GET /api/publications/:id` | 查询快照、配图、链接和事件时间线。 |
| `PATCH /api/publications/:id` | 更正日期、时间、链接或备注；必填原因和 `requestKey`，事务内写更正事件。 |
| `POST /api/publications/:id/void` | 作废记录；必填原因和 `requestKey`，事务内写作废事件。 |

发布操作在 `ContentOperations` 或独立的 `PublicationOperations` 中实现，并通过 `WorkbenchService` 门面共享数据库上下文；控制器只接收参数。事务内锁定目标稿件，核对稿件存在、平台一致、状态为“已审核/已发布”，核对所选图片均属于该选题和平台，保存正文快照、图片关联、创建事件，再更新稿件状态与最近发布缓存。任何一步失败均回滚。相同 `requestKey` 重试返回已有记录；同一个键携带不同内容应返回冲突。新登记不会调用 Runware、Humanizer 或 Baoyu。

服务端校验 `publishedOn` 为真实 `YYYY-MM-DD` 日期；`publishedTime` 为 `HH:mm`；日期过滤、月份统计统一按 `Asia/Shanghai` 业务日。链接可为空；有值时只接受 `http/https`、去除首尾空白并限制长度。关键词分页、页码和页大小设置上限。更正或作废在事务中锁定发布记录；同值更正不新增事件，作废后再次作废返回当前结果。页面不显示任何自动发布承诺。

## 7. 稿件状态与统计

- `drafts.status` 表示**当前工作稿**的状态。登记后为“已发布”；后续修改正文或新增素材仍按现有规则退回“草稿”并重新审核，历史发布记录不受影响。当前工作稿状态不能用来推断过去是否发布过。
- 作废最后一条有效记录时，如果当前工作稿仍是“已发布”，按原有审核标记退回“已审核”或“草稿”；如果工作稿已因编辑回到“草稿”，作废历史不改变这个状态。
- 历史页一条代表一次发布。`本月已发布 X 篇` 用有效记录按 `draft_id` 去重；如需展示操作次数，单独写“发布 X 次”。旧数据回填记录计入相应月份，但标明来源。
- 更正发布日期后按新日期重新计算月份；作废后从统计中排除。日期过滤以 `published_on` 为准，录入时间只在详情显示。
- 现有“内容日历”仍按选题计划日期查询，不混入实际发布日期；两个入口名称和空状态保持明确。

## 9. 验收与验证

1. 同一选题分别在知乎、小红书、公众号登记后，历史显示三条平台记录；同平台再次登记保留两次日期和链接，旧记录不被覆盖。
2. 新记录的文本与选中图片固定在登记时；修改工作稿、重新生成图片、刷新页面后，历史详情仍显示原快照。旧数据只显示可确认的日期和链接。
3. 发布接口失败或重复点击不会生成半条记录、重复事件或重复图片关联；同请求标识重试返回同一条记录。
4. 更正日期或链接留下前后值及原因；作废记录可在历史中查到，但不计入默认列表和本月统计。
5. 发布后编辑稿件使其回到草稿，历史记录仍可查；该工作稿未重新审核前不能再次登记发布。
6. 有发布记录的选题不能硬删除，接口返回可读提示；无发布记录的选题仍可删除。迁移和重复启动不覆盖旧数据、不重复回填。
7. `/content?view=publications` 直达与刷新、平台/日期/关键词筛选、分页、详情、外链、空状态、加载/错误状态、窄屏和明暗主题均在浏览器走通。
8. “本月已发布”与历史页按北京时间同一口径；多次发布同一稿件在“篇”统计中只计一次，作废或更正后数字同步变化。

验证时运行 `npm run build`、`npm run test:ui-logic`；API 集成测试仅连接一次性、可丢弃的 PostgreSQL 测试库运行 `npm run test:api`。使用假实现或既有测试数据，不调用真实付费模型，也不访问外部平台发布接口。
